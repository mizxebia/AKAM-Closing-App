# Video Demo — What to Cover

A suggested structure for a Closing Management System walkthrough video, target length **8–9 minutes**. Each scene maps to a numbered section in `02-voice-script.md` and `03-video-script.md`.

| # | Scene | What it shows | Target length |
|---|---|---|---|
| 0 | Title / Intro | Title card, one-line pitch of the app | 0:10 |
| 1 | App Shell & Navigation | Top nav bar, logo, Help Center button, signed-in user | 0:15 |
| 2 | Dashboard | Stat cards, search, status tabs, sortable table, refresh | 0:45 |
| 3 | Create a New Closing Ticket | Slide-out form, building lookup, flags, **Coop Transfer auto-behavior** (Buyer T-Code + Yardi flag + confirm popup), validation | 1:15 |
| 4 | Closing Ticket Workspace overview | Header, Domecile/Yardi quick links, failure banner, ticket lifecycle/status explanation, 4 tabs | 0:35 |
| 5 | Closing Details tab | Parties, transaction, closing agent, document uploads, RPTT rule, Move to Post Closing | 0:50 |
| 6 | Invoice tab | Add payments, invoice table, totals, Generate/View Invoice PDF | 1:00 |
| 7 | Yardi Charges tab | Scheduled charges, add charge, unpaid charges, Auto Move Charges, TBD warning, Buyer/Seller ledgers, Check with Invoice | 1:20 |
| 8 | New Owner Ticket tab | Generate ticket, form sections, occupancy rule, document viewer, Validate button + requirements | 1:05 |
| 9 | Help Center | Quick Reference search, Process Overview flowchart, Payments/Yardi/New Owner guides | 0:35 |
| 10 | Closing Recap | Full status lifecycle recap (Draft → Completed), key rules callout | 0:25 |
| 11 | Outro | Summary card, call to action / contact | 0:10 |

**Total: ~8:20**

## Things to have ready before recording
- A test environment with at least one ticket in **every** status (Draft, Processing, Ready for Post Closing, Post Closing, Validate Closings, Transferring Building, Completed, Failed) so each screen has real data.
- One ticket specifically set up as **Coop Transfer** to demo the Buyer T-Code auto-behavior.
- A ticket with a generated Invoice PDF and a generated New Owner Ticket PDF, so the document viewer and "View Invoice" flows aren't empty.
- A ticket with both Scheduled and Unpaid Yardi charges (including one still marked "TBD") to show the validation warning.
- A ticket close to Validate-ready, so the Validate button and its requirement checklist can be shown.

## Recommended tone
Calm, confident, walkthrough-style narration — like showing a colleague around, not a hard sales pitch. Plain language, short sentences, no jargon unless it's a term the app itself uses (e.g. "T-Code", "RPTT").
