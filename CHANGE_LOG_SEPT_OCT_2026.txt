============================================================
HOW TO READ THIS FILE
============================================================
This is a chronological log of every change made to the AKAM Closing
Management System (a React/TypeScript Power Apps "code app" backed by
Dataverse) over the past ~5-6 weeks, plus related process/tooling work.

STATUS KEY:
  DEPLOYED        = Confirmed on GitHub (master branch) AND deployed to
                     the Power Apps Dev environment as of Oct 8, 2026.
  COMMITTED       = Confirmed pushed to GitHub master. Standalone Power
                     Apps deployment for this specific change was not
                     independently re-verified (see note below).
  NEEDS CONFIG    = Code is written and deployed, but requires a
                     non-code action (e.g. setting a value in the Power
                     Platform admin center) before it's fully functional.
  OPEN / FOLLOW-UP = Known gap or decision point, not yet actioned.

IMPORTANT NOTE ON DEPLOYMENT STATUS:
As of Oct 8, 2026, the entire current codebase (every item below) has
been built, pushed to GitHub master, and deployed to the Power Apps Dev
environment in one final push. So from a "is it live right now" point
of view, everything below is live in Dev. The DEPLOYED/COMMITTED
distinction below instead reflects how directly each change was
verified during this engagement — items marked COMMITTED were authored
earlier (by teammates or in earlier sessions) and are included for
completeness from git history, not independently re-tested here.

       transaction-type option set (e.g. "ReadyForPostClosing" became
       "Ready For Post Closing") — fixed two status-badge color-lookup

       (the column was deleted in Dataverse — it's now merged into

       dialog-driven.

SECTION 2 — OPEN ITEMS / FOLLOW-UPS
============================================================

A. NSC_Charges_Check_Date has no value set in Dev [NEEDS CONFIG]
   The environment variable "cr109_NSC_Charges_Check_Date" currently
   has neither a default value nor an override value configured in
   the Dev Power Platform environment. Until a number is set (via the
   Power Platform admin center / maker portal), the Validate
   confirmation dialog can't compute a suggested Charges Start Date
   and will open directly into manual date-entry mode instead. The
   user noted this is expected for now — production will get the real
   value — but Dev should get a default value set if anyone wants to
   test the auto-suggestion path before prod is configured.

B. Power Apps deployment tooling [OPEN / FOLLOW-UP — informational]
   The legacy `pac code push` CLI command currently fails against this
   app with an HTTP 400 "workflowDetails" deserialization error (a
   schema mismatch between that CLI and the current service), even
   after updating `pac` to the latest version (2.12.2). The npm-based
   CLI (`npx power-apps push --non-interactive`) works reliably and
   should be used for all future deployments instead.

C. Pre-existing lint debt [OPEN / FOLLOW-UP — low priority]
   A number of `react-hooks/set-state-in-effect` and
   `react-refresh/only-export-components` findings exist across the
   codebase (e.g. BuildingCodeLookup.tsx, ClosingTicketTable.tsx,
   DocumentViewerPanel.tsx, NewOwnerTicketTab.tsx, and others). These
   predate this engagement's changes, have been repeatedly verified as
   not introduced by any of the work above, and are not blocking —
   listed here only as a possible future cleanup task.

D. Bundle size [RESOLVED, informational]
   The production JS bundle crossed Vite's 500kB warning threshold
   briefly during this period; it was addressed earlier via vendor
   chunk-splitting (framer-motion, lucide-react, @radix-ui,
   @microsoft/power-apps split into separate chunks) and dead
   dependency removal (react-pdf, pdfjs-dist, which were unused). The
   bundle is currently back under the warning threshold.

E. charges/invoice line-item save failures — audit logging scope
   [OPEN / FOLLOW-UP — low priority]
   The "APP FAILURE" logging pass (item 14 above) covered ticket-level
   operations but intentionally did not extend into the Charges/
   Invoices workspace's own Save All / Save Payments error paths,
   since those already have decent inline error banners. Flagged in
   case consistent audit-log coverage there becomes a priority later.

SECTION 3 — KEY TECHNICAL CONTEXT (for reference)
============================================================

- Stack: React 19 + TypeScript (strict) + Vite 7 + Tailwind CSS v4,
  running as a Microsoft Power Apps "code app" against Dataverse via
  @microsoft/power-apps SDK.
- Repo: github.com/mizxebia/AKAM-Closing-App, branch "master".
- Power Apps Dev environment ID: e1cba263-6407-ef71-82d5-197403fb0d06.
- `src/generated/` is auto-generated from the Dataverse schema — never
  hand-edited; regenerated via `npx power-apps refresh-data-source`
  (whole schema) or `npx power-apps add-data-source` (adding a new
  table as a data source).
- Critical build-verification rule: `tsc --noEmit -p .` does NOT type-
  check this project (the tsconfig is solution-style with "files": []).
  Always use `npx tsc -b` or the full `npm run build` instead.
